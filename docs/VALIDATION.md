# Problem validation and pilots

No interviews, pilot commitments, or adoption results are recorded yet.

## Questions for maintainers

1. What was your last installation or quickstart failure that normal tests missed?
2. Do you run documentation examples against built wheels outside the checkout today?
3. What do pytest-examples, Runme, rundoc, or your existing CI already solve?
4. Would a five-minute setup and a separate CI check be acceptable? What would prevent adoption?
5. Would you try a prototype against one concrete example and report whether you retain it?

## Evidence to record

With permission, record project, workflow, failure reproduction, current workaround, proposed benefit, setup time, and pilot decision. Keep private discussions and personal data outside the public repository. Prefer links to already public issues and minimal original fixtures.

Proceed after five workflow reviews, two real failure cases, and three willing pilots. These thresholds are internal decision aids, not promises of traction. Document contrary evidence too. If validation fails, narrow the proposal or contribute an integration to an existing tool.

## Pilot success

Record installation time, defect caught, false positives, CI overhead, and whether the maintainer retains the check after one month. An initial trial is not sustained adoption. Request permission before publishing quotations or project endorsements.
