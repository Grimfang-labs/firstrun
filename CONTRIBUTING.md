# Contributing to FirstRun

FirstRun is in planning. There are no build, install, or test commands yet. Start with [the specification](docs/SPEC.md), [roadmap](docs/ROADMAP.md), and open issues.

Useful contributions now include a minimal packaging failure, a comparison with an existing workflow, a specification correction, and pilot feedback. Discuss significant scope changes before implementation.

## Workflow

1. Check existing issues; describe the problem and desired observable outcome.
2. For a reproduction, include OS, Python version, package/build tool versions, expected versus actual behavior, and a minimal redistributable example. Remove credentials and private data.
3. Fork the repository, make a focused branch, and open a PR linking the issue.
4. Explain the change and evidence. Once implementation exists, bug fixes should include a failing-before/passing-after regression test.

Review considers usefulness, correctness, maintainability, documentation, and cross-platform behavior. Substantial documentation contributions are welcome. AI-assisted contributions must be understood and verified by their author; the author remains responsible for correctness and rights to contributed content.

Maintainers aim to respond within three working days when capacity permits. Contributions are licensed under the repository's MIT license. Keep discussion respectful and follow the [code of conduct](CODE_OF_CONDUCT.md).
